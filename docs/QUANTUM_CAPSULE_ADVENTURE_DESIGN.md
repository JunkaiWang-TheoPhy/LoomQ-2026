# Quantum Capsule：太空舱入口与冒险基地设计

**文档状态**：可实施设计稿
**目标**：把现有 Quantum World 冒险内容包装成一个容易进入、可以反复返回、结果可核验的太空舱旅程。

## 1. 设计判断

太空舱是玩家进入游戏后的第一空间，也是所有功能的“母港”。它负责建立方向感、解释最少必要的量子概念、给出第一个可完成的维修任务，并把玩家送入现有的 Quantum World 冒险基地。冒险基地沿用既有案件、实验协议和证据护照；本设计只新增一扇可见的舱门，让玩家随时返回太空舱。

因此，空间关系固定为：

```text
封面 → 太空舱（母港） → 量子引擎维修 → 量子操作台
                         ↓
                    舱门 / 空间站入口
                         ↓
                 既有 Quantum World 冒险基地
                         ↘ 舱门返回太空舱
```

“量子飞船由量子原理驱动”是叙事设定。可核验的技术结果仍来自本地模拟器、统一 QASM/IR、ProofTrace、Hybrid path certificate，以及用户主动配置后的真机运行记录。界面不能把模拟结果标成真机结果。

## 2. 首次进入：30 秒内让玩家做出一次选择

### 2.1 封面与警报

封面结束后直接切入太空舱，不要求先填表或配置模型。播放一段短警报、低频引擎声和三次闪烁的感叹号；动画必须支持“减少动态效果”。警报文案只说一件事：

> 量子引擎的两个观测分支没有同步。先修复它，再决定是否出航。

感叹号指向引擎舱，点击后进入维修卡片。玩家可以跳过音效，但不能跳过第一个可操作动作。

### 2.2 量子引擎维修

维修任务使用 Bell 入门电路作为第一件“可摸到的部件”：

1. 手册只展示三张卡：`H` 是“制造均匀叠加”、`CX` 是“让两个比特建立条件关系”、测量是“把结果读出来”。
2. 系统预填一个预测选项，玩家也可以改写预测：`保留 CX 后，00/11 会成为主要结果`。
3. 玩家点击一次“运行 A/B 对照”：A 保留 `CX`，B 移除 `CX`。
4. 页面同时展示两个直方图、第一处分歧 `g2 · CX`、一句白话解释和一个“维修完成”按钮。
5. 完成后生成第一张 `Inquiry Passport`，护照记录预测、QASM、counts、结论和运行模式（本地模拟 / 真机）。

维修成功的判据是结果链完整，不是玩家答对一句话。错误预测也可以完成任务，系统会把它保存为一次可复盘的学习记录。

## 3. 太空舱四个固定区域

### 手册舱

手册是场景中的可点击物件，同时提供右侧抽屉式阅读层。每一页对应一个当前任务所需概念，概念首次出现时在按钮旁显示 12 字以内的解释。阅读进度、已解锁词条和“回到任务”位置持久化保存。

### 船员档案

自我介绍不是独立表单，而是“船员档案”：展示玩家昵称、已完成章节、实验护照、真机凭证是否已配置，以及最近一次结论。所有信息默认本地保存；凭证只读环境变量，不进入档案或仓库。

### 任务甲板

任务甲板列出三种状态：`待处理`、`进行中`、`已归档`。第一项固定为量子引擎维修；维修完成后出现“进入冒险基地”。甲板要显示下一步动作和预计时长，例如“阅读 1 分钟”“运行 10 秒”，让新手知道自己不会被带进无底洞。

### 量子操作台

操作台有三层渐进式入口：

- **快速实验**：预置 Bell/GHZ、自然语言输入、运行本地模拟器。
- **自由演示**：编辑白名单 OpenQASM 2.0，查看 IR、目标分布、ProofTrace 和 Hybrid 分支证书。
- **真实设备**：用户显式选择 OriginQ 或 SpinQ，读取环境变量中的凭证，提交 job，并把原始 JSON、job ID、时间戳和统计摘要写入证据区。

真机入口必须标注“可选、需要账号/凭证、受平台开放时段影响”。本地路径永远可用，且与真机结果用不同颜色和标签呈现。

## 4. 冒险基地：沿用旧内容，新增返回门

冒险基地复用现有 Quantum Atlas 案件、章节状态、实验协议和证据护照，不再复制一套手册或控制台。玩家从太空舱进入后，直接落到上次未完成的案件节点；若首次进入，则从既有序章开始。

基地新增一个稳定地标：**返回太空舱的舱门**。舱门在地图中始终可见，靠近后显示“返回太空舱”；点击不清空案件状态，只保存当前章节、最近一次实验和护照索引。返回后，太空舱的任务甲板会显示“冒险基地：第 N 章进行中”，让两个空间互相解释。

冒险基地仍然遵守原有规则：故事情节不冒充实验结果，量子实验只回答对应的可观测问题，不能验证的命题保留为 `inconclusive`。新增舱门只是导航和状态持久化，不改变案件内容或科学结论。

## 5. 玩家状态与证据状态

```json
{
  "home": {"engine_repaired": true, "manual_pages": ["h", "cx", "measure"]},
  "adventure": {"case_id": "eighty-years", "chapter": 3, "return_door_seen": true},
  "evidence": {"passport_ids": ["passport-001"], "last_mode": "local_sim"},
  "hardware": {"originq": "unconfigured", "spinq": "unconfigured"}
}
```

状态写入 local storage 或现有会话状态接口；服务器端不保存凭证。每次返回门跳转都带上当前 case/chapter，不允许因路由切换丢失进度。护照和证书是只追加记录，玩家可以重放实验，但不能覆盖旧结果。

## 6. 评审演示路径

评委在三分钟内应能完成：

1. 看见太空舱警报并点击引擎；
2. 阅读三张概念卡，修改或确认预测；
3. 运行一次本地 A/B Bell 对照并看到 `g2 · CX`；
4. 打开第一张护照；
5. 通过舱门进入既有冒险基地；
6. 在基地内打开返回门，回到太空舱且进度不丢失；
7. 在操作台看到本地模拟与真机入口的明确区别。

## 7. 实施验收清单

- 首屏不依赖 LLM 环境变量即可完成维修；
- 警报、感叹号和舱门均有键盘焦点、文本标签和减少动态效果路径；
- 首次任务只引入 `H`、`CX`、测量三个概念；
- A/B 运行结果、首个分歧和护照均来自真实 API；
- 冒险基地沿用现有案件和章节数据；
- 返回门不会重置 case/chapter/passport；
- 真机凭证只来自环境变量，页面不展示密钥；
- 本地模拟、真机返回、失败和等待状态有明确标签；
- README、Markdown、DOCX、PPTX 互相链接，提交 PR 可直接打开。

## 8. 交付边界

本次设计交付的是入口空间、维修任务、区域导航、状态契约和评审路径。既有 Quantum World 案件本体、ProofTrace、Witness Chain、Hybrid path certificate 和适配器继续作为底层能力复用；后续实现应优先接入现有 API，不另起一套并行运行时。
